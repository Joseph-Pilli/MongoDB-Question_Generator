# MongoDB Question Generator — Documentation

## 1. Overview

**MongoDB Question Generator** is a local web application that converts company assignments or syllabus concepts into **complete, exam-ready MongoDB/Mongoose coding question packages**.

An instructor or content author pastes an assignment (or uploads a document), reviews syllabus coverage, selects concepts, and clicks **Generate**. The app produces three synchronized folders plus a downloadable ZIP:

| Folder | Purpose |
|--------|---------|
| `{slug}_prefilled` | What the **student receives** — empty implementable files + scaffold |
| `{slug}_solution` | **Reference solution** — full working code |
| `{slug}_tests` | **Automated tests** — Jest + Supertest + MongoMemoryServer |

**Run:** `python app.py` → open `http://127.0.0.1:5000`

---

## 2. Problem It Solves

| Without this app | With this app |
|------------------|---------------|
| Manual question writing takes hours | One package in ~1–3 minutes (OpenRouter) |
| Inconsistent folder structure across questions | Structure driven by query + rules |
| README, tests, and solution drift apart | Single generation pass keeps them aligned |
| Questions accidentally include out-of-syllabus topics | Hard syllabus guardrails + validation |
| Students get partial scaffold with hidden answers | Clear split: empty student files vs scaffold |

---

## 3. Target Syllabus

**MongoDB Integration & Data Management** — 8 canonical topics only:

1. Schema design  
2. CRUD operations  
3. Aggregation pipeline  
4. Indexing  
5. Data validation  
6. Pagination and sorting  
7. Relationships between collections  
8. Error handling  

The generator **rejects** SQL, Prisma, JWT/auth, Redis, WebSockets, file uploads, and other out-of-scope technologies.

---

## 4. Architecture

```
Browser (index.html + script.js)
        │
        ▼ POST /analyze ──► assignment_analyzer.py  (instant local keyword scan)
        │
        ▼ POST /generate ─► claude_client.py
        │                      │
        │                      ├─ file_spec_parser.py  (parse implement vs forbidden files)
        │                      ├─ llm_client.py         (OpenRouter or Cursor API)
        │                      └─ validate_response()    (JSON, syllabus, tests, README)
        │
        ▼ write_question_package ─► file_writer.py ─► output/{slug}_prefilled|solution|tests
        │
        ▼ GET /download/{slug} ──► zip_question() ──► ZIP download
```

### Key modules

| Module | Role |
|--------|------|
| `app.py` | Flask routes: `/`, `/analyze`, `/generate`, `/download` |
| `lib/assignment_analyzer.py` | Maps assignment text → syllabus coverage (green/red) |
| `lib/file_spec_parser.py` | Infers which folders user asked for (models/routes only, etc.) |
| `lib/claude_client.py` | LLM call, JSON repair, validation, retry logic |
| `lib/llm_client.py` | OpenRouter (`sk-or-...`) or Cursor (`crsr_...`) API |
| `lib/file_writer.py` | Writes 3 folders, manifest, ZIP (OneDrive-safe cleanup) |
| `lib/syllabus.py` | Single source of truth for allowed topics |
| `prompts/system_prompt.md` | LLM instructions for question shape |
| `prompts/readme_reference.md` | Reference README format (Pet Adoption Portal style) |

## 5. User Workflow

### Step 1 — Input assignment
- **Paste text** or **upload** `.txt`, `.md`, `.pdf`, `.docx` (max 5 MB)

### Step 2 — Optional configuration
- **Question title** (auto-generated if blank)
- **Files students must implement** (one path per line)
- **Pre-filled files (do NOT modify)** (default: `server.js`, `app.http`)
- **Domain** (e.g. hospital, e-commerce)

If file lists are left blank, the app **parses the assignment text** (e.g. "models + routes, no controllers").

### Step 3 — Analyze
- Instant local scan — no API call
- Shows **covered** vs **not covered** syllabus topics
- Flags out-of-syllabus concepts (JWT, Redis, etc.)

### Step 4 — Select concepts & Generate
- Check concepts to include in the question
- LLM generates full JSON package
- Validation enforces syllabus, file structure, README format, test IDs

### Step 5 — Preview & Download
- Preview `_prefilled`, `_solution`, `_tests` in browser
- Download ZIP with all three folders

## 6. Output Package Structure

### Injected automatically (not in LLM JSON)
- `db.js` — MongoMemoryServer connection  
- `package.json` — Express, Mongoose, Jest dependencies  
- `.gitignore`  
- `README.md` — in prefilled only (from `readme_md`)

### Generated by LLM
- `server.js`, `app.http` — scaffold (complete in prefilled)
- `models/`, `routes/`, optional `controllers/`, etc. — **empty in prefilled**, full in solution
- `.tests/index.test.js` — Jest tests with `NJSCPAxxxxx` IDs

### README format (reference)
- Title + scenario  
- Database section  
- Schema section(s)  
- API endpoints with request/response examples  
- Folder structure tree  
- `<MultiLineNote>` — pre-filled vs student files  

---

## 7. File Specification Rules

**Highest priority:** what the user explicitly requests.

| User says | Generated |
|-----------|-----------|
| models + routes, no controllers | `models/*.js`, `routes/*.js` only |
| models + controllers + routes | all three folders |
| exactly 2 models (customer, client) | only those two model files |

**Prefilled rule:** student implement files are **empty** (`""`) or one comment line.  
**Scaffold rule:** `server.js`, `app.http` are complete in prefilled.

---

## 8. Validation & Quality Gates

Before a package is accepted:

1. Valid JSON (with `json-repair` fallback)  
2. Syllabus topics ⊆ allowed 8 topics  
3. No forbidden keywords (SQL, JWT, etc.)  
4. `prefilled` and `solution` have **identical file paths**  
5. Student files empty in prefilled, complete in solution  
6. Forbidden folders absent (e.g. no `controllers/` if not requested)  
7. README contains required sections + `<MultiLineNote>`  
8. Tests use `:::NJSCPA<5_ALNUM>_TEST_SUITE:::` and unique `it()` IDs  
9. Duplicate test IDs auto-fixed before validation  

Failed generation **retries once** with stricter JSON/structure hints.

## 9. Configuration (`.env`)

```env
CURSOR_API_KEY=sk-or-v1-...    # OpenRouter key (auto-detected)
# or
CURSOR_API_KEY=crsr_...        # Cursor Cloud Agents key

MODEL_NAME=claude-sonnet-4-6   # Maps to anthropic/claude-sonnet-4.6 on OpenRouter
```

| Key prefix | Provider | Typical speed |
|------------|----------|---------------|
| `sk-or-` | OpenRouter chat API | ~30–90 seconds |
| `crsr_` | Cursor Cloud Agents | ~5–15 minutes |

## 10. Utility & Use Cases

1. **Corporate training** — Paste client assignment → exam question in minutes  
2. **University labs** — Align MongoDB assessments to a fixed syllabus  
3. **Interview prep** — Generate CRUD / aggregation / relationship drills  
4. **Content scaling** — Same quality bar across many questions  
5. **Automated grading** — Bundled Jest tests enable auto-evaluation  

---

## 11. Limitations

- Requires API key (OpenRouter credits or Cursor subscription)  
- LLM output quality varies; retry may be needed  
- OneDrive on Windows can lock stale folders (ZIP uses manifest to exclude them)  
- Analyze is keyword-based (fast but not semantic)  
- Generate is single-question per run (no batch mode)
